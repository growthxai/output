---
title: "v0.15.0 → v0.16.0"
description: "Upgrading Output.ai projects from v0.15.0 to v0.16.0: package consolidation, new peer dependencies, provider-native web search costs, HTTP response parsing changes, and worker concurrency defaults."
---

This guide covers the move of `@outputai/http`, `@outputai/llm` and `@outputai/evals` into `@outputai/core`. None of these packages is published anymore: their APIs now live at `@outputai/core/http`, `@outputai/core/llm` and `@outputai/core/evals`. The http and llm exports are unchanged; the evals LLM judges moved to `@outputai/core/llm`, and the evals internals are no longer exported. The `@outputai/output` umbrella package is not published anymore either: projects depend on `@outputai/core` and `@outputai/cli` directly.

Smaller breaks come with them: `ky`, `undici` and `ai` are now peer dependencies of `@outputai/core`, the AI SDK provider packages are no longer installed for you, provider-native web search charges are included in normalized LLM costs, and `sendHttpRequest()` parses some response bodies differently.

Separately, the worker no longer sets defaults for two workflow concurrency variables, and one telemetry field is renamed. See [Worker defaults and telemetry](#worker-defaults-and-telemetry).

## What changed

- `@outputai/http` is replaced by the `@outputai/core/http` subpath. `outputFetch`, `createKyClient`, `addRequestCost`, and the `ky` and `undici` re-exports are unchanged.
- `@outputai/llm` is replaced by the `@outputai/core/llm` subpath. `generateText`, `generateTextWithStreaming`, `streamText`, `generateImage`, `Agent`, `loadPrompt`, `registerProvider`, `getProviderNames`, and the `aiSdk` re-export are unchanged.
- `@outputai/evals` is replaced by the `@outputai/core/evals` subpath. `evalWorkflow`, `verify`, `Verdict`, `VERDICT`, `CRITICALITY`, `DatasetSchema`, `EvalOutputSchema`, and the eval types are unchanged.
- `judgeVerdict`, `judgeScore`, `judgeBoolean`, `judgeLabel`, and the `JudgeArgs` type moved to `@outputai/core/llm`, with the same arguments and results.
- `interpretResult`, `aggregateCaseVerdict`, `renderEvalOutput`, `computeExitCode`, `getEvalWorkflowName`, `isEvalWorkflow`, `getParentWorkflowName`, and the other Zod schemas of `@outputai/evals` (`VerdictSchema`, `CriticalitySchema`, `InterpretConfigSchema`, `EvaluatorResultSchema`, `EvalCaseSchema`, `LastOutputSchema`, `LastEvalSchema`) are no longer exported.
- Steps and evaluators referenced as values in workflow files, rather than called, are replaced with their activity names in the workflow bundle. Previously their modules were bundled into the workflow sandbox when the file had no activity calls.
- The `output-workflow-bundle` package export condition is no longer used when bundling workflows. Packages resolve through their `import`, `module`, `webpack` or `default` conditions.
- `@outputai/output` is no longer published. New projects depend on `@outputai/core` and, as a dev dependency, `@outputai/cli`. `output fix` replaces an existing `@outputai/output` dependency with both.
- `ky` (`>=2 <3`), `undici` (`>=8 <9`) and `ai` (`>=7 <8`) are peer dependencies of `@outputai/core`.
- The built-in AI SDK provider packages are optional peer dependencies of `@outputai/core`, so they are no longer installed automatically. Using a provider whose package is missing throws a `FatalError` naming the package.
- `getProviderNames()` lists only the built-in providers whose package is installed, plus registered ones.
- Normalized LLM metering records Anthropic and OpenAI native web searches as `tools` usage and includes their charges in `cost.tools` and `cost.total`.
- Google Vertex grounding pricing now includes Gemini 4 per-query charges. Existing Gemini 2 prompt pricing and Gemini 3 query pricing remain supported.
- The legacy `cost:llm:request` event and `llm:usage` trace attribute remain token-only and unchanged.
- `sendHttpRequest()` returns XML, form-urlencoded, and JavaScript response bodies as text instead of base64, and returns empty or invalid JSON bodies as raw text instead of throwing.
- With `OUTPUT_TRACE_HTTP_VERBOSE` on, HTTP request and response bodies in trace files are parsed the same way as `sendHttpRequest()`. Multipart bodies are stored as base64.

## Migration steps

### Update imports

Replace every import of `@outputai/http` with `@outputai/core/http`, every import of `@outputai/llm` with `@outputai/core/llm`, and every import of `@outputai/evals` with `@outputai/core/evals`, including module mocks in tests. Import the LLM judges from `@outputai/core/llm`:

```ts
// Before
import { createKyClient, addRequestCost } from '@outputai/http';
import { generateText, aiSdk } from '@outputai/llm';
import { verify, Verdict, judgeVerdict } from '@outputai/evals';
vi.mock( '@outputai/http', () => ( { outputFetch: vi.fn() } ) );
vi.mock( '@outputai/llm' );

// After
import { createKyClient, addRequestCost } from '@outputai/core/http';
import { generateText, aiSdk, judgeVerdict } from '@outputai/core/llm';
import { verify, Verdict } from '@outputai/core/evals';
vi.mock( '@outputai/core/http', () => ( { outputFetch: vi.fn() } ) );
vi.mock( '@outputai/core/llm' );
```

If you used one of the exports that were removed from `@outputai/evals`, copy its logic into your project. `output workflow test` still interprets, aggregates and renders eval results the same way.

### Replace `@outputai/output`

If your project depends on `@outputai/output`, replace it with `@outputai/core` in `dependencies` and `@outputai/cli` in `devDependencies`:

```jsonc
// Before
"dependencies": {
  "@outputai/output": "0.15.0"
}

// After
"dependencies": {
  "@outputai/core": "0.16.0"
},
"devDependencies": {
  "@outputai/cli": "0.16.0"
}
```

`npx @outputai/cli@0.16.0 fix` makes this change for you, keeping the version you had. Bump both packages to `0.16.0` afterwards.

### Remove the dependencies

Delete `@outputai/http`, `@outputai/llm` and `@outputai/evals` from `dependencies`, `devDependencies`, and `peerDependencies` in `package.json`. Bump `@outputai/core` and `@outputai/cli` to `0.16.0`.

### Install the peer dependencies

npm 7+ and pnpm install required peer dependencies automatically. With other package managers, or if your install reports missing peers, add them yourself:

```bash
npm install ky@2 undici@8 ai@7
```

If your project already depends on `ky`, `undici` or `ai`, make sure the versions fall in the supported ranges.

### Install the AI SDK providers you use

The provider packages are optional peers, so no package manager installs them for you. Add the ones your prompts reference in their `provider` field:

| `provider` | Package |
|------------|---------|
| `amazon-bedrock` | `@ai-sdk/amazon-bedrock@5` |
| `anthropic` | `@ai-sdk/anthropic@4` |
| `azure` | `@ai-sdk/azure@4` |
| `google-vertex` | `@ai-sdk/google-vertex@5` |
| `openai` | `@ai-sdk/openai@4` |
| `perplexity` | `@ai-sdk/perplexity@4` |

For example, a project with Anthropic and OpenAI prompts:

```bash
npm install @ai-sdk/anthropic@4 @ai-sdk/openai@4
```

A prompt that uses a provider whose package is missing fails with `Provider "<name>" requires the "<package>" package, which is not installed`. Providers added with `registerProvider()` are not affected.

### Re-check normalized LLM metering

If you consume the `llm:generation:metering` event or the `llm:generation:usage` and `llm:generation:cost` trace attributes, account for native web search tool items:

- Anthropic searches use the `web_search` label.
- OpenAI searches use `web_search` or `web_search_preview`. An ambiguous variant is retained as unpriced `web_search_unknown`.
- Tool charges appear in `cost.tools` and are included in `cost.total`. Code that expects only token items or calculates token spend from `cost.total` must handle them separately.

The legacy `cost:llm:request` event and `llm:usage` trace attribute still exclude tool charges.

### Re-check `sendHttpRequest()` response bodies

This only affects calls with `responseOptions.includeBody: true`:

| Response | Before | After |
|----------|--------|-------|
| `application/xml`, `*+xml` | base64 string | text |
| `application/x-www-form-urlencoded` | base64 string | text |
| `application/javascript` | base64 string | text |
| JSON content type with an empty body | throws | `''` |
| JSON content type with an invalid body | throws | raw text |

Remove any base64 decoding of those content types. If you relied on the error to detect a bad JSON response, check whether `body` is a string instead.

### Re-check trace file readers

If you parse trace files recorded with `OUTPUT_TRACE_HTTP_VERBOSE` on, request and response bodies now follow the table above, and multipart request bodies are base64 strings.

## Worker defaults and telemetry

No code changes are needed, but the worker behaves differently if you never set its concurrency variables, and one telemetry field is renamed.

### Workflow concurrency defaults

The worker no longer sets defaults for these two variables. When they are unset, `@temporalio/worker` applies its own:

| Variable | v0.15.0 | v0.16.0 |
|----------|---------|---------|
| `TEMPORAL_MAX_CACHED_WORKFLOWS` | `1000` | Sized from the isolate's heap limit |
| `TEMPORAL_MAX_CONCURRENT_WORKFLOW_TASK_EXECUTIONS` | `200` | `40` |

The cache size is `(heap limit in MiB - 200) * 600 / 1024`, with a minimum of 10. With `--max-old-space-size=4096` that is about 2,400 cached workflows. The formula assumes roughly 600 cached workflows per GB of heap, so if your workflows hold large inputs, outputs, or step results, set `TEMPORAL_MAX_CACHED_WORKFLOWS` explicitly.

If you relied on 200 concurrent workflow tasks, set `TEMPORAL_MAX_CONCURRENT_WORKFLOW_TASK_EXECUTIONS=200`. Keep it at or below `TEMPORAL_MAX_CACHED_WORKFLOWS`.

The resolved values are logged at startup in the `Worker sizing` record, as `maxCachedWorkflows` and `workflowTaskSlots`.

### New startup warnings

After the `Worker sizing` record, the worker logs a warning in either or both of these cases, each with the values it compared:

| Warning | Cause | Fix |
|---------|-------|-----|
| `Worker isolates may commit more heap than the host allows` | The heap limit times the isolate count exceeds the container's memory limit, or the machine's when there is no container. A `NODE_OPTIONS` heap cap applies to each isolate, and the worker runs one on its main thread plus one per workflow thread. | Lower the `NODE_OPTIONS` heap cap so the isolate count times the cap fits. |
| `Worker runs more workflow tasks than it can cache, forcing replays` | `TEMPORAL_MAX_CONCURRENT_WORKFLOW_TASK_EXECUTIONS` resolves above `TEMPORAL_MAX_CACHED_WORKFLOWS`. | Lower the task executions or raise the cache. |

A project that only set `TEMPORAL_MAX_CACHED_WORKFLOWS` below `40` will now see the second warning, because task executions default to `40`. See [Memory and Isolates](/operations/worker-tuning#memory-and-isolates).

A Dockerfile copied from an earlier version of the [Railway](/operations/deployment/railway) or [Render](/operations/deployment/render) guide sets `--max-old-space-size-percentage=80`, which triggers the first warning because the worker runs two isolates by default. Those guides now use `40`.

### Telemetry field rename

If you enable `OUTPUT_WORKER_TELEMETRY_INTERVAL_MS` and parse the periodic `Worker` log, `memory.constrainedMemory` is now `memory.memoryLimit`.

The old field reported `process.constrainedMemory()` directly, which returns a sentinel near 2^64 when the process has no memory limit. `memoryLimit` reports the container's limit, or the machine's total memory when there is none.

Two fields were added to the same block: `memory.nonMainHeap` (`rss - heapUsed`) and `memory.heapSizeLimit`.

## Checklist

- Replace the `@outputai/output` dependency with `@outputai/core` and, as a dev dependency, `@outputai/cli`, both at `0.16.0`.
- Replace `@outputai/http` imports and mocks with `@outputai/core/http`, and remove the dependency.
- Replace `@outputai/llm` imports and mocks with `@outputai/core/llm`, and remove the dependency.
- Replace `@outputai/evals` imports and mocks with `@outputai/core/evals`, import the judges from `@outputai/core/llm`, and remove the dependency.
- Install `ky@2`, `undici@8` and `ai@7` if your package manager does not install peer dependencies.
- Install the `@ai-sdk/*` provider packages your prompts use.
- Update normalized LLM metering consumers to handle native web search tool items and charges.
- Remove base64 decoding of XML, form-urlencoded, and JavaScript response bodies from `sendHttpRequest()`.
- Set `TEMPORAL_MAX_CACHED_WORKFLOWS` and `TEMPORAL_MAX_CONCURRENT_WORKFLOW_TASK_EXECUTIONS` explicitly if you relied on the old defaults or your workflows hold large state.
- Lower `--max-old-space-size-percentage` to `40` if your Dockerfile uses the earlier Railway or Render value of `80`.
- Rename `memory.constrainedMemory` to `memory.memoryLimit` in anything that parses worker telemetry.
